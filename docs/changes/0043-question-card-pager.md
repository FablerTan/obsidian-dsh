# 0043 提问卡片对齐官方：单题一屏 + 底部翻页 + 草稿可回改

> 对应路线图 [R-26](../roadmap.md#需求待办)。用户 2026-10-27 给出两张截图对比：插件现状（平铺、选项带边框、自填框在每题下、只有一个「提交答案」）
> vs 官方弹窗（小标题 + 大标题、复选框/序号行、说明与标签同排、「推荐」徽标、底部 `‹ 1/1 ›` 翻页 + `跳过` / `提交`）。

## 1. 背景与问题

dsh 侧 `ask_user_question` 的**一批问题是一次性下发的**（`dsh-user-questions` 的 `AskUserQuestionRequest.questions[]`），
答案也按整批回传（`answers[]`，跳过的题用 `{ id, selected: [] }` 表示）。插件旧的 `QuestionCard` 把整批问题纵向平铺：

| 问题 | 根因 |
|---|---|
| 多题时第二题被挤到卡片外，必须先看完/答完第一题 | 整批平铺 + 卡片高度不受控，窄面板里只能纵向滚 |
| 提交后无法回改 | 只有一个「提交答案」直接整批提交，没有分页与草稿回看 |
| 排版与官方差距大 | 选项是「标签一行 + 说明一行」的卡片式按钮（带边框/底色），没有复选框/序号、没有「推荐」徽标、说明不与标签同排；头部只有一个「需要回答」，缺真正的小标题与标题层级 |
| 自填答案位置 | 每题下面各挂一个输入框，多题时重复出现 |

官方实现（`dsh-client-ui-user-questions/lib/client.js`）的关键行为，本提案逐条对齐：

1. 一屏一题，`drafts[]` 按题保存；`‹ n/N ›` 翻页，草稿跨页保留，可回改。
2. 单选点选项**自动翻到下一题**；自填内容与选项互斥（单选填了自填就清掉选中）。
3. 底部 `跳过`：把该题记为 skipped 并翻页/整批提交；`提交`：先校验整批（未答且未跳过 → 跳回该题并提示），再整批提交。
4. 选项行：左侧复选框（多选）/ 序号（单选），右侧「标签 + 推荐徽标 + 说明」同排、可换行；自填行与选项行同排版。
5. 字号层级：小标题（eyebrow）12px 次要色 → 标题 15/16px 500 → 选项文字 13/14px，说明同号次要色。

## 2. 目标与非目标

- 目标：提问卡片**单题一屏 + 底部翻页**，翻页保留草稿、可回改；底部 `跳过` / `提交` 与官方一致（含未答校验）；
  选项/自填行的排版、字号、间距、复选框与「推荐」徽标对齐官方；卡片超高时只滚内容区，头部与底栏固定。
- 非目标：不引入官方的「收起 / 关闭（cancel）」按钮（桥没有 cancel API，见路径 B）；不改审批卡片；不改 dsh 侧桥协议与答案格式；
  不做键盘 ←/→ 翻页快捷键（官方也没有）。

## 3. 实现路径调研（≥ 2 条）

| 路径 | 做法 / 关键代码位置 | 改动面 | 代价与风险 | 结论 |
|---|---|---|---|---|
| **A（本次落地）** | 纯视图层改造：`pending.tsx` 的 `QuestionCard` 引入 `index` + `drafts[]`（`{ selected, custom, skipped }`），实现翻页 / 自动前进 / 跳过 / 整批校验提交；`styles.css` 重排头部、选项、自填行与底栏，卡片 `max-height: min(60vh, 520px)` + 卡内滚动 | `pending.tsx`、`styles.css` | 低；数据面不动，答案仍是整批 `answers[]`，dsh 侧零改动 | **推荐** |
| B | 在 A 基础上做「逐题提交 + 可取消」：每题提交后立即回传部分答案，并支持官方头部的收起 / 关闭 | 需要桥新增 `questionAnswerPartial` / `questionCancel` 与 dsh 侧 pending 生命周期配合 | 高；dsh 的 `ask()` 是一次性 Promise，部分答案与取消都要跨进程协议改动，且 `DUPLICATE_PROVIDER` / 单写者语义要重验 | 否（记为后续候选） |
| C | 直接复用官方 `dsh-client-ui-user-questions` 组件 | — | 不可行：那是 dsh Web GUI 的 client 插件，依赖 `@deepseek-ai/dsh-client-ui-primitives` 与 `--dsw-*` 设计变量，插件里没有这些运行时与主题 token | 否 |

**推荐 A**：用户要的是「同一批问题的呈现与回改」，答案模型本来就是整批，视图层翻页即可；协议层改动收益低、风险高。

## 5. 行为变化

- 一次一批多题时：**一屏一题**，底部 `‹ 1/2 ›` 翻页；翻页不清草稿，可回改；单选点选项自动到下一题。
- `跳过` 把当前题记为跳过（回传 `{ id, selected: [] }`）；`提交` 先校验整批，未答且未跳过的题会跳回并提示「还有未回答的问题」。
- 选项行改为官方式排版：多选左侧复选框、单选左侧序号；标签、`推荐` 徽标与说明同排换行；自填答案作为选项列表最后一行（无选项的题目用整块输入框）。
- 卡片最高 `min(60vh, 520px)`，超高时只滚内容区，头部「需要回答」与底部翻页/按钮固定可见。
- 审批卡片、`plan-review` 的降级提示、桥协议与答案格式均不变。

## 6. 风险与回滚

| 风险 | 影响 | 回滚方式 |
|---|---|---|
| 单题时多出翻页条 | 视觉噪音（官方同样保留 `1/1`） | 与官方保持一致，保留 |
| 整批提交前必须先「看完」每题 | 用户若只想答一题，需用 `跳过` 其余题 | `跳过` 即官方语义，且答案里保留空题 |
| 长选项/长说明换行导致卡片变高 | 触发卡内滚动 | `max-height` 上限 + 内容区滚动，头部/底栏不受影响 |
| 覆盖 Obsidian `button` 默认样式 | 其它按钮样式的选择器同域冲突 | 只用「父类 + button」限定在提问卡内，回滚只改这一段 CSS |
