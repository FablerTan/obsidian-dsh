# 0054 目标条固定到运行提示下方（composer 渲染顺序 RunStatus → goalBar）

> 对应路线图 [R-37](../roadmap.md#需求待办)。用户原话：目标条要「始终显示在运行提示（深度求索中）下方」——否则每轮运行提示开关会把目标条顶动。
> 按 [AGENTS.md](../../AGENTS.md) 规则 12 例外（用户当轮明确指定要改的具体项）直接执行并补提案记录。
> [0053](0053-goal-bar-flicker.md) 已解决「闪烁 / 残影」；本提案只解决**位置**：运行提示在上、目标条在下。

## 1. 背景与问题

0052 把目标条挂在 `Composer` 的 `goalBar` 槽，0053 把它从半透明模糊底改成了主题实色卡片，闪烁已由用户确认消失。但**位置**仍不合用户预期：

- `composer.tsx` 原来的渲染顺序是 `goalBar` → `RunStatus` → 输入卡，即目标条在输入框上方最外层、运行提示夹在目标条与输入卡之间；
- goal 自动续跑时运行提示每轮出现 / 消失，夹在中间的这一行会把目标条和输入卡之间的关系来回拉扯（目标条被顶开、与输入卡脱节），看起来就是目标条被「顶动」；
- 用户明确要求：目标条要**始终显示在运行提示（「深度求索中」）下方**，并且紧贴输入框。

### 影响范围

只影响原生聊天面板输入框上方的排布顺序。目标条的数据、动作、外观（0053 的实色卡片）与运行提示（0047 / 0048）本身的行为都不变。

## 2. 目标与非目标

### 目标

- 目标条固定在**运行提示下方、输入卡之上**：DOM 顺序为 `RunStatus` → `goalBar` → 输入卡，目标条与输入卡紧邻；
- 运行提示出现 / 消失时，目标条与输入卡作为整体一起移动（相对位置恒定），不再出现目标条被运行提示顶开、与输入卡脱节的抖动；
- 无运行提示（不在运行）时目标条仍是输入卡正上方的一张卡片；无目标时目标条不占位；
- 只调顺序，不改渲染逻辑、不改其它 composer 子节点（待处理卡 / 压缩提示 / 警告条 / 只读提示）的相对顺序。

### 非目标

- 不改运行提示（0047 / 0048）的位置设置与默认（备选路径 B 不采用）；
- 不改目标条的尺寸 / 外观 / 动作与编辑（0052 / 0053 已定）；
- 不改桥协议、不改 dsh 源码、不 bump 版本号。

| 路径 | 做法 / 关键代码位置 | 改动面 | 代价与风险 | 结论 |

## 5. 行为变化

- 输入框上方的顺序变为：**运行提示（深度求索中）在上 → 目标条在下 → 输入卡**；目标条与输入卡紧贴，不再被运行提示夹在中间。
- 运行提示出现 / 消失时，目标条与输入卡一起上下移动（相对位置恒定），不再出现目标条被顶开、与输入卡脱节的抖动。
- 没有运行提示时（不在运行），目标条仍是输入卡正上方的一张卡片；没有目标时目标条不占位；两者都没有时不占任何高度。
- 其它 composer 子节点（待处理卡 / 「正在压缩会话历史…」提示 / 模型警告条 / 只读提示）与输入卡的相对顺序不变。
- 目标条外观（0053 的实色卡片）、阶段标签、动作、内联编辑、降级行为全部不变。

## 6. 风险与回滚

| 风险 | 影响 | 回滚方式 |
|---|---|---|
| 顺序调整影响其它 composer 子节点 | 待处理卡 / 压缩提示等错位 | 只动了 `RunStatus` 与 `goalBar` 两个相邻节点，其余节点顺序未变；如异常换回顺序即可 |
| 运行提示在 0048 的「输出最下方」档时 | 上方的运行提示不在 composer 里，目标条自然成为输入卡上方第一张卡 | 符合预期（该档下运行提示本来就不在上面），无需处理 |
| 回滚 | — | 把 `goalBar` 移回 `RunStatus` 之前（一行顺序）即可 |

整体回滚：还原 `composer.tsx` 的一处顺序 → `npm run build` → 重载插件；无数据迁移、不涉及桥与服务。
