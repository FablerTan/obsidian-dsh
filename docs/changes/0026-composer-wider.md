# 0026 输入框横向加宽（卡片略宽于正文）

## 1. 背景与问题

[0019](0019-native-panel-fullbleed.md) 把 header / composer 的水平内边距统一为 27px，让输入卡片与时间线正文列左右边界完全对齐。
实际使用中这个「完全等宽」让底部输入区的视觉重心偏窄、显得不稳：正文列是满宽的连续文本，而输入卡片是带边框和阴影的实体块，两者等宽时卡片看起来反而比文字列小。

用户要求：输入框横向**稍微加宽**，比正文文字内容宽一点即可。

## 2. 目标与非目标

- 目标：输入卡片左右各外扩约 11px（面板宽 432px 时，卡片 378px → 400px）；卡内文字的左右边界仍与正文列对齐（27px）。
- 非目标：
  - 不改 header、时间线正文列、消息气泡的宽度；
  - 不改输入框高度、字号、圆角、阴影、颜色；
  - 不改 `composer.tsx` 等任何 TS/TSX 逻辑（纯视觉）。

## 3. 实现路径调研（≥ 2 条）

| 路径 | 做法 / 关键代码位置 | 改动面 | 代价与风险 | 结论 |
|---|---|---|---|---|
| A（采用） | 直接改 [styles.css](../../styles.css) 的 `.dsh-native-composer` 水平内边距：`6px 27px 10px` → `6px 16px 10px`。卡内文字的 27px 由「16px 内边距 + 1px 边框 + 10px textarea 内边距」自然凑回 | 1 行 CSS + 1 行注释 | 数值依赖 textarea 的 10px 内边距，改输入框内边距时要同步复核；无逻辑风险 | **采用**：显式、可读，菜单（`@` / `/`）与待审批卡片都随外层一起加宽 |
| B | 保持 composer 27px，给 `.dsh-native-input-wrap` 加 `margin: 0 -11px`（或 `width: calc(100% + 22px)`） | 1 行 CSS | 同样是纯 CSS，但「负外边距」比正内边距更难读，且 wrap 若再加子元素容易溢出；效果与 A 等价 | 不采用：可读性更差 |
| C | 连时间线正文列一起加宽（timeline 左右 padding 12px → 6px） | 1–2 行 CSS | 正文每行变长，改变排版节奏；用户明确只要输入框 | 不采用：超出需求 |

> 用户当轮已明确指定「把输入框加宽一点」，按 [AGENTS.md](../../AGENTS.md) 规则 12 的例外直接执行；本提案用于留痕，不再等选路。业务上没有第二条更优路径，A 与 B 等价而 A 更可读。

## 4. 改动清单

| 文件 | 改动 |
|---|---|
| [styles.css](../../styles.css) | `.dsh-native-composer` 的 `padding` 由 `6px 27px 10px` 改为 `6px 16px 10px`，并加注释说明「卡片外扩 11px、卡内文字仍对齐正文」 |

## 5. 行为变化

- 输入卡片左右各向面板边缘靠近 11px（面板 432px 宽时：卡片 378px → 400px，左右边距 27px → 16px）。
- 输入框内的占位符、正文光标仍落在与时间线正文相同的 27px 左边界上；右侧发送按钮随卡片右移到 16px 内边距处。
- `@` / `/` 菜单、待审批 / 待回答卡片都嵌在 `.dsh-native-composer` 或 `.dsh-native-input-wrap` 内，宽度随卡片同步变化（菜单与输入卡片左右对齐）。
- 其余布局（header、正文列、消息气泡）不变。

## 6. 风险与回滚

| 风险 | 影响 | 回滚方式 |
|---|---|---|
| 窄侧栏下卡片离面板边缘太近 | 视觉上偏挤（16px 仍留有余量） | 把 16px 调回 20–22px |
| 以后调 textarea 内边距导致卡内文字错位 | 卡内文字不再对齐正文 | 同步调整 composer 水平内边距，保持「两者之和 = 27px」 |
| 整体回滚 | — | `git checkout -- styles.css` |
